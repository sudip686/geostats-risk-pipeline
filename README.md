# Tanga Pipeline (Current)

## One command
```bash
python scripts/run_pipeline.py
```

Pipeline steps:
1. Variogram reproduction diagnostics.
2. Internal validation (MODEL_OK vs SGS + assay/domain comparisons).
3. Submission package build and strict checklist validation.

## Single source of truth
Submission generation is driven by one canonical run and one config:
- Run directory must satisfy strict constraints:
  - `n_real = 200`
  - `search_radius_m = [250,120,70]`
  - variogram tuning enabled
  - trend enabled
  - calibration enabled
- Config: `config/project_best_fit.yaml`
- Truth manifests:
  - `build/source_of_truth.submission.json`
  - `build/source_of_truth.internal.json`

## Submission outputs
Primary package folder:
- `submission_ready/`

Generated by:
- `python scripts/build_submission_package.py --strict`

Key outputs:
- Template-style docs in `submission_ready/`:
  - `Title page.docx`
  - `Covering Letter-MS.docx`
  - `SG Manuscript.docx`
  - `Authors Statement.docx`
  - `Conflict of interest.docx`
  - `Declaration of interest statement.docx`
  - `Fig.docx`
  - `Table.docx`
- Source-of-truth marker files:
  - `submission_ready/source_of_truth.submission.json`
  - `submission_ready/SOURCE_OF_TRUTH.md`
- Zip artifacts:
  - `submission_package_final_clean.zip`
  - `submission_ready/submission_package_final_clean.zip`
- Checklist:
  - `SUBMISSION_CHECKLIST.md` (root)

## Notes
- Do not manually edit generated numeric content in `manuscript.md`, `tables.md`, `figure_captions.md`.
- Do not use `scripts/publish.py` (removed from active workflow).
- Keep `output/` as the active run-output root; move historical variants to `_archive_YYYYMMDD/`.
